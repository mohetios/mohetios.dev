## یادداشت‌های مطالعه

_Refactoring UI_ کتاب طراحی برای کسانی است که با جزئیات پیاده‌سازی فکر می‌کنند.

ایده‌ی اصلی‌اش این است که interface بهتر می‌تواند از چند تکنیک تکرارپذیر بیاید. لازم نیست منتظر اعتمادبه‌نفس هنری بمانی تا hierarchy، فاصله‌گذاری، تایپوگرافی، رنگ، عمق و empty state را بهتر کنی.

برای مهندس محصولی که نسخه‌ی اول ابزار را اغلب پیش از آمدن designer می‌سازد، به‌خصوص مفید است.

## ایده‌های مفید

### از feature شروع کن

کتاب با شروع طراحی از یک layout خالی مخالف است. از کاری شروع کن که interface باید انجام دهد، بعد ساختاری انتخاب کن که به همان کار کمک کند.

این‌طور طراحی به رفتار گره می‌خورد، نه به تزئین.

### اول hierarchy، بعد styling

خیلی از interfaceهای ضعیف به‌خاطر palette زشت ضعیف نیستند؛ مبهم‌اند چون همه‌چیز وزن بصری یکسانی دارد. اندازه، وزن، contrast و فاصله باید نشان دهند اول چه چیزی مهم است.

### سیستم بهتر از حدس

مقیاس فاصله، مقیاس type، طیف رنگ و الگوی component انتخاب‌های تصادفی را کم می‌کنند. یک سیستم کوچک، هم طراحی و هم پیاده‌سازی صفحه‌ی بعدی را آسان‌تر می‌کند.

## چرا نزدیک نگهش می‌دارم

مرجع عملی برای اینکه UI خامی که developer ساخته به چیزی خوانا، سنجیده و قابل ship تبدیل شود. کمتر به سلیقه مربوط است و بیشتر به اینکه مشکل‌های رایج interface را سریع ببینی.
