## یادداشت‌های مطالعه

_React Key Concepts_ کتاب خوبی برای تثبیت دانسته‌هاست. شروع React آسان است؛ کار اصلی این است که یاد بگیری کدام بخش‌های مدل باید ساده بمانند و کدام‌ها ساختار سنجیده می‌خواهند.

ارزش کتاب در یک مقدمه‌ی دیگر بر JSX نیست؛ در این است که مدام به component، prop، state، effect، composition و جریان داده در interface برمی‌گردد.

## ایده‌های مفید

### component یعنی مرز

component خوب React فقط یک تکه‌ی بصری نیست؛ مرزی است دور رفتار، نیاز داده و تصمیم‌های render.

### state صاحب می‌خواهد

خیلی از مشکل‌های React از مبهم‌بودن مالکیت state می‌آیند. سؤال معمولاً این نیست که «state کجا می‌تواند باشد؟»، بلکه این است که «کدام بخش interface مسئول تغییر آن است؟»

### به effect باید شک کرد

effect مفید است، اما همان‌جایی است که component ساده سخت‌فهم می‌شود. codebase React وقتی بهتر می‌شود که effect را نقطه‌ی integration ببینیم، نه ابزار پیش‌فرض.

## چرا نزدیک نگهش می‌دارم

مرور عملی برای کار frontend. پیش از رفتن سراغ framework، state management یا abstraction بیشتر، بحث React را به اصول برمی‌گرداند.
